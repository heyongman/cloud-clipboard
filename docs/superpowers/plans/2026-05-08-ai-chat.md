# AI Chat Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an authenticated AI chat page using OpenAI-compatible Responses API with streaming, image input, image generation, web search, browser-saved conversations, role presets, summaries, settings, and token/context display.

**Architecture:** The Node backend owns AI provider settings and proxies all OpenAI-compatible REST calls so API keys never reach the browser. The Vue frontend stores conversations locally and renders a NextChat-style chat workspace using existing Vue 2, Vuetify 2, axios, and markdown-it patterns.

**Tech Stack:** Vue 2 Options API, Vuetify 2, axios, markdown-it, Koa, `@koa/router`, ESM modules, Node 18 native `fetch`, Node `node:test`.

### Task 2: Backend OpenAI Payload And Streaming Helpers

**Files:**
- Create: `server-node/app/ai/model-context.js`
- Create: `server-node/app/ai/openai-client.js`
- Create: `server-node/app/ai/stream.js`
- Test: `server-node/tests/ai-openai-client.test.mjs`
- Test: `server-node/tests/ai-stream.test.mjs`

- [ ] **Step 1: Implement context metadata**

Export `getModelContextWindow(modelId)` and `getKnownModelContexts()`. Include conservative known values for current common model families and return `null` for unknown models.

- [ ] **Step 2: Implement Responses payload builder**

`buildResponsesPayload({ model, reasoningEffort, rolePrompt, messages, tools })` returns:

```js
{
    model,
    stream: true,
    instructions: rolePrompt || undefined,
    reasoning: { effort: reasoningEffort },
    tools: [{ type: 'web_search' }, { type: 'image_generation' }],
    input: [...]
}
```

Only include `reasoning` and `tools` when values are present. Convert frontend `{ type: 'text' }` to `input_text`, and `{ type: 'image' }` to `input_image`.

- [ ] **Step 3: Implement REST helpers**

Use native `fetch` for:

- `listModels(config)`
- `createStreamingResponse(config, payload)`
- `createSummary(config, payload)`

Validate that `apiKey` exists before calling upstream.

- [ ] **Step 4: Implement token estimates**

Use a local approximation: CJK characters count as 1 token, ASCII groups count roughly 1 token per 4 chars, and image attachments add a fixed estimate. This is labelled as an estimate in the API response.

- [ ] **Step 5: Implement SSE parsing**

Parse `event:` and `data:` lines. Normalize upstream `response.output_text.delta`, `response.completed`, image generation results, and errors into downstream events.

- [ ] **Step 6: Add tests**

Test payload conversion, enabled tools, omitted optional fields, token estimation, context lookup, text delta parsing, completion usage parsing, and image result normalization.
